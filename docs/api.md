# API reference

Base URL, local development: `http://localhost:4000`

All request and response bodies are JSON. Every successful response wraps its payload in a
`data` key. Every failure uses one envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Some fields are invalid",
    "details": [{ "field": "priceCents", "message": "Price must be at least R0.50" }]
  }
}
```

`details` is only present when there is something field-specific to report.

---

## Conventions

| Topic | Rule |
| --- | --- |
| Money | Always an integer number of **cents**. `3200` means `R32.00`. Never send a decimal. |
| Timestamps | ISO 8601 strings, UTC (`2026-11-10T09:14:22.000Z`). |
| IDs | UUID v4 for menu items and orders. |
| Order numbers | Human-facing `ORD-0001`, sequential, generated by the server. |
| Auth | `Authorization: Bearer <jwt>` on every staff route. |
| Rate limits | 300 requests / 15 min per IP overall; 20 order creations / 10 min; 10 logins / 15 min. |
| Status codes | `200` ok, `201` created, `204` no content, `400` validation, `401` unauthenticated, `403` forbidden, `404` missing, `409` conflict, `429` rate limited, `503` dependency down. |

### Error codes

| Code | Status | Meaning |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | A field failed a Zod schema. Check `details`. |
| `UNAUTHORIZED` | 401 | Missing, malformed or expired bearer token. |
| `INVALID_CREDENTIALS` | 401 | Wrong staff username or password. |
| `FORBIDDEN` | 403 | Token is valid but not a staff token. |
| `CORS_BLOCKED` | 403 | Origin not in `FRONTEND_URL` (production only). |
| `NOT_FOUND` | 404 | Route does not exist. |
| `MENU_ITEM_NOT_FOUND` | 404 | No menu item with that id. |
| `ORDER_NOT_FOUND` | 404 | No order with that id. |
| `ITEM_UNAVAILABLE` | 409 | The item is marked sold out. |
| `ITEM_IN_USE` | 409 | Cannot delete an item that is in an open order. |
| `INVALID_TRANSITION` | 409 | Status change skipped a step or moved backwards. |
| `RATE_LIMITED` | 429 | Too many requests. |
| `INTERNAL_ERROR` | 500 | Unexpected server error. The real cause is logged, never returned. |

## Health

### `GET /api/health`

Public. Used by Render health checks and by the client to explain "API unreachable" clearly.

```json
{
  "status": "ok",
  "service": "coffee-shop-api",
  "uptimeSeconds": 412,
  "timestamp": "2026-11-10T09:14:22.000Z",
  "dependencies": {
    "store": { "driver": "redis", "ok": true }
  }
}
```

Returns `503` with `"status": "degraded"` when the store ping fails.

## Menu

### `GET /api/menu`

Public. Lists menu items sorted by name.

| Query | Type | Notes |
| --- | --- | --- |
| `category` | `coffee` \| `tea` \| `pastry` \| `other` | Optional. Invalid values return `400`. |
| `available` | `true` \| `false` | Optional. Anything else is ignored rather than coerced. |

```json
{
  "data": [
    {
      "id": "6f1c1b6e-2b1a-4b8e-9a55-3f0c2a9d1e77",
      "name": "Flat White",
      "description": "Ristretto shots with silky micro-foam.",
      "priceCents": 3400,
      "category": "coffee",
      "available": true,
      "createdAt": "2026-11-01T07:02:11.000Z",
      "updatedAt": "2026-11-01T07:02:11.000Z"
    }
  ],
  "count": 1
}
```

### `GET /api/menu/:id`

Public. `404 MENU_ITEM_NOT_FOUND` when the id is unknown.

### `POST /api/menu` — staff

```json
{
  "name": "Cortado",
  "description": "Equal parts espresso and warm milk.",
  "priceCents": 3000,
  "category": "coffee",
  "available": true
}
```

| Field | Rules |
| --- | --- |
| `name` | 2–80 characters, trimmed. |
| `description` | 0–300 characters, optional, defaults to `""`. |
| `priceCents` | Integer 50–500000. |
| `category` | One of `coffee`, `tea`, `pastry`, `other`. |
| `available` | Boolean, optional, defaults to `true`. |

`201 Created`, `Location: /api/menu/:id`, body `{ "data": <item> }`.

### `PUT /api/menu/:id` — staff

Partial update. Send only the fields that change. Sending an empty object returns
`400 VALIDATION_ERROR` ("Provide at least one field to update").

Changing `category` rewrites both category index sets in one transaction.

### `DELETE /api/menu/:id` — staff

`204 No Content` on success.

`409 ITEM_IN_USE` if the item appears in any order that is `pending`, `preparing` or `ready`.
Mark it unavailable instead — the message says so.

## Orders

### `POST /api/orders` — public

The client never sends a price. The server reads current menu prices, snapshots them onto each
line and recomputes the total.

```json
{
  "customerName": "Thabo Mokoena",
  "note": "Oat milk, extra hot",
  "items": [
    { "itemId": "6f1c1b6e-2b1a-4b8e-9a55-3f0c2a9d1e77", "qty": 2 },
    { "itemId": "0a9d2c44-1f3e-4a21-8b77-77c1e0b9a2aa", "qty": 1 }
  ]
}
```

| Field | Rules |
| --- | --- |
| `customerName` | 2–60 characters. |
| `note` | 0–200 characters, optional. |
| `items` | 1–30 lines. Each `qty` is an integer 1–20. |
| `itemId` | Must exist and be available. |

Duplicate `itemId` lines are merged before pricing, so sending the same drink twice cannot
create two lines.

`201 Created`:

```json
{
  "data": {
    "id": "9c2f0a1e-77b4-4c31-8f5a-0d2b7e9c4a10",
    "orderNumber": "ORD-0007",
    "customerName": "Thabo Mokoena",
    "note": "Oat milk, extra hot",
    "items": [
      {
        "itemId": "6f1c1b6e-2b1a-4b8e-9a55-3f0c2a9d1e77",
        "name": "Flat White",
        "priceCents": 3400,
        "qty": 2,
        "lineTotalCents": 6800
      }
    ],
    "totalCents": 6800,
    "status": "pending",
    "createdAt": "2026-11-10T09:14:22.000Z",
    "updatedAt": "2026-11-10T09:14:22.000Z"
  }
}
```

`409 ITEM_UNAVAILABLE` names the item that is sold out.

### `GET /api/orders/:id` — public

Needed so a customer can open their confirmation link and poll the status. `404` when unknown.

### `GET /api/orders` — staff

| Query | Type | Notes |
| --- | --- | --- |
| `status` | `pending` \| `preparing` \| `ready` \| `collected` | Optional. |
| `date` | `YYYY-MM-DD` | Optional. Malformed dates return `400`. |

With neither filter, returns every order newest first.

### `GET /api/orders/summary/today` — staff

```json
{
  "data": {
    "date": "2026-11-10",
    "orderCount": 12,
    "revenueCents": 43800,
    "byStatus": { "pending": 2, "preparing": 3, "ready": 1, "collected": 6 }
  }
}
```

### `PATCH /api/orders/:id/status` — staff

```json
{ "status": "preparing" }
```

The workflow is forward-only:

```
pending ──▶ preparing ──▶ ready ──▶ collected
```

Sending the current status is a no-op that returns `200`. Skipping a step, or moving backwards,
returns `409 INVALID_TRANSITION` with the allowed next states:

```json
{
  "error": {
    "code": "INVALID_TRANSITION",
    "message": "Cannot move an order from \"pending\" to \"collected\"",
    "details": { "allowed": ["preparing"] }
  }
}
```

This is enforced in the repository, not the UI. Calling the API directly cannot bypass it.

## Auth

### `POST /api/auth/login`

```json
{ "username": "staff", "password": "<your-staff-password>" }
```

```json
{
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "staff": { "username": "staff" }
  }
}
```

`401 INVALID_CREDENTIALS` for a wrong username or password. The message never says which one
was wrong.

The token is signed with `JWT_SECRET` and carries `{ sub, role: "staff" }`. It expires after
`JWT_EXPIRES_IN` (default 8 hours). There is no refresh endpoint — sign in again.

---

## Trying it with curl

```bash
# Health
curl http://localhost:4000/api/health

# Menu
curl http://localhost:4000/api/menu

# Log in and keep the token
TOKEN=$(curl -s -X POST http://localhost:4000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"staff","password":"<your-staff-password>"}' | jq -r .data.token)

# Place an order
curl -X POST http://localhost:4000/api/orders \
  -H 'Content-Type: application/json' \
  -d '{"customerName":"Thabo","items":[{"itemId":"PASTE_ID","qty":2}]}'

# Advance it
curl -X PATCH http://localhost:4000/api/orders/PASTE_ORDER_ID/status \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"status":"preparing"}'
```
